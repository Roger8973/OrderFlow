## ADDED Requirements

### Requirement: API retrieves a customer by id
The system SHALL expose a `GET /customers/{id}` endpoint that, when a customer with that `id` exists, responds with HTTP 200 and a JSON body containing that customer's `id`, `name`, `email`, `phone`, and `isActive`, as currently stored. The body SHALL have the same shape as the body returned when the customer was created. Customers SHALL be retrievable regardless of their active state.

#### Scenario: Existing customer is retrieved
- **WHEN** a customer was created with `name` "Maria Silva", `email` "maria@example.com", and `phone` "+55 11 99999-0000", and a client sends `GET /customers/{id}` with that customer's `id`
- **THEN** the system responds with HTTP 200
- **THEN** the response body contains that `id`, `name` "Maria Silva", `email` "maria@example.com", `phone` "+55 11 99999-0000", and `isActive` true

#### Scenario: Customer without a phone is retrieved
- **WHEN** a customer was created without a `phone` and a client sends `GET /customers/{id}` with that customer's `id`
- **THEN** the system responds with HTTP 200
- **THEN** the response body reports `phone` as null

#### Scenario: Retrieved data reflects normalization applied at creation
- **WHEN** a customer was created with `name` "  Maria Silva  " and `email` "Maria@Example.com", and a client sends `GET /customers/{id}` with that customer's `id`
- **THEN** the response body contains `name` "Maria Silva" and `email` "maria@example.com"

#### Scenario: Retrieved customer matches the created customer
- **WHEN** a client creates a customer and then sends `GET` to the URL in the creation response's `Location` header
- **THEN** the system responds with HTTP 200 and a body equal to the body returned by the creation request

### Requirement: Unknown customer id is reported as not found
The system SHALL respond to `GET /customers/{id}` with HTTP 404 and an RFC 7807 problem-details body when no customer has the given `id`. A path segment that is not a well-formed GUID SHALL also be answered with HTTP 404, since no customer can be identified by it.

#### Scenario: No customer has the id
- **WHEN** a client sends `GET /customers/{id}` with a well-formed GUID that does not belong to any customer
- **THEN** the system responds with HTTP 404 with a problem-details body

#### Scenario: Id is not a GUID
- **WHEN** a client sends `GET /customers/not-a-guid`
- **THEN** the system responds with HTTP 404

### Requirement: Customer retrieval is documented in the API description
The system SHALL describe the retrieve-customer endpoint, its `id` path parameter, and its 200 and 404 responses in the generated OpenAPI document.

#### Scenario: Retrieval endpoint appears in OpenAPI
- **WHEN** a client retrieves the generated OpenAPI document
- **THEN** it contains a `GET /customers/{id}` operation documenting the `id` path parameter and the 200 and 404 responses

## MODIFIED Requirements

### Requirement: API registers a new customer
The system SHALL expose a `POST /customers` endpoint that accepts a customer `name`, `email`, and optional `phone` as a JSON body and, on success, creates the customer and responds with HTTP 201, a `Location` header containing the URL at which the created customer can be retrieved (`/customers/{id}`), and a JSON body containing the created customer's `id`, `name`, `email`, `phone`, and `isActive`.

#### Scenario: Customer is created with all fields
- **WHEN** a client sends `POST /customers` with a valid `name`, a valid `email`, and a `phone`
- **THEN** the system responds with HTTP 201
- **THEN** the response body contains a system-generated `id` and echoes the submitted `name`, `email`, and `phone`

#### Scenario: Customer is created without a phone
- **WHEN** a client sends `POST /customers` with a valid `name` and `email` and no `phone`
- **THEN** the system responds with HTTP 201
- **THEN** the response body reports `phone` as null

#### Scenario: Client-supplied id is ignored
- **WHEN** a client sends `POST /customers` with an `id` property in the body
- **THEN** the created customer's `id` is generated by the system and differs from the supplied value

#### Scenario: Location header identifies the created customer
- **WHEN** a client successfully creates a customer
- **THEN** the response has a `Location` header whose path is `/customers/{id}`, where `{id}` is the `id` in the response body
